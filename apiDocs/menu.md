# 菜单管理

菜单分为目录（`menuType=1`）和菜单（`menuType=2`）。菜单权限通过角色关联。新建菜单后自动关联超级管理员角色；`builtIn=true` 的内置菜单不能修改或删除。

所有接口均为 `POST`，需要 `Authorization: Bearer <token>`，并要求调用者拥有 `manage_menu` 菜单权限。

## 列表

`POST /api/menu/list`，请求体 `{}`。

返回全量菜单，包含停用、隐藏和内置菜单，客户端按 `parentId` 组树。响应数据为 `{ "list": [...] }`。

## 新增

`POST /api/menu/create`。菜单 ID 由服务器生成，请求不再携带 `menuId`：顶级菜单依次为 10000、20000……；子孙菜单在所属顶级目录的段内自增（10001、10002……），每段最多 9999 个，超出返回 `100037`。移动到其他顶级目录的菜单保留原 ID。校验父级目录和字段。顶级目录必须提交 `scope`（1 平台，2 项目）；子项的范围跟随上级，提交值被忽略。类型为菜单（`menuType=2`）时 `routeName` 必填；非空 `routeName` 在全部菜单中唯一，重复返回 `100030`。校验通过后写入菜单；平台菜单自动关联超级管理员，项目菜单不需要关联（超级管理员在项目中直接拥有全部项目菜单）。

新增时必填 `menuId`，手动指定唯一正整数，不使用自增序列生成接口中的菜单 ID。上限为 `9007199254740991`，保证前端数字精度。已存在的 ID 返回 `100026`。

```json
{
  "menuId": 301,
  "parentId": 300,
  "menuType": 2,
  "name": "数据查询",
  "icon": "",
  "routeName": "data_query",
  "routePath": "/data/query",
  "status": 1,
  "hidden": false,
  "sort": 1
}
```

父级 ID 为 `300`、子级 ID 为 `301` / `302` 是手动编号约定，实际父子关系仍由 `parentId` 决定，不根据 ID 数字推断。菜单插入和超级管理员关联在同一事务中完成。

已有表使用 `GENERATED BY DEFAULT AS IDENTITY`，允许显式插入手动指定的 ID，因此无需重建表或修改已有菜单 ID。MyBatis-Plus 实体使用 `IdType.INPUT`。

## 修改

`POST /api/menu/update`。先校验菜单存在、父级合法、`routeName` 规则（同新增）和目录子项约束；范围变化时，有子项返回 `100032`，没有子项则清除该菜单原有的角色关联，变为平台菜单时自动关联超级管理员；内置菜单返回 `100017`。

## 删除

`POST /api/menu/remove`。目录有子项返回 `100011`，内置菜单返回 `100017`。

校验通过后，先删除该菜单的全部 `role_menu` 关联，再删除菜单记录；两个操作处于同一事务，失败时回滚，避免 `fk_role_menu_menu` 外键错误。不删除角色，不递归删除子菜单。

参考：[MyBatis-Plus 主键策略](https://baomidou.com/en/reference/annotation/)、[PostgreSQL identity 字段](https://www.postgresql.org/docs/current/ddl-identity-columns.html)、[Spring 事务回滚](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/rolling-back.html)。

错误：`100001` 参数不合法，`100003` 未登录，`100009` 菜单不存在，`100010` 父级不合法，`100011` 目录非空，`100015` 目录不能改菜单，`100016` 无权访问，`100017` 内置菜单不可变更，`100026` 菜单 ID 已存在。
